# Super Simple Speedo v13.2.1 — Diagnostics startup regression fix

## Root cause confirmed

v13.1 Live Intelligence called `escapeHtml(...)` but no such helper existed. When Diagnostics Mode was enabled, the startup `DIAGNOSTIC_SESSION / RESUMED` event immediately invoked the Live Intelligence renderer. That threw `ReferenceError: escapeHtml is not defined` before the launch-button listener had been attached. The result was exactly the field symptom: a perfectly rendered startup screen with an inert “Let’s go!” button and incomplete later UI initialisation.

## Fixes

- Added the missing safe HTML-escaping helper.
- Bound the launch button before any optional diagnostics/session initialisation.
- Isolated diagnostics UI rendering with a failure boundary so instrumentation can never stop GPS/startup.
- Made diagnostic archive-status callbacks failure-safe.
- Kept the v13.2 service-worker/cache integrity changes.
- Kept the startup disclaimer and Live Intelligence.

Diagnostics are now explicitly non-critical: a debug-display bug must never prevent the speedometer from starting.
